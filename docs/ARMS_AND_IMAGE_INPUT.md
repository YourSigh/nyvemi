# 手臂与拆层图片输入修复（0.18.1）

旧实现将两手放在同一个 `arm` 层，再绕完整画布中心旋转。挥手带动两手，把连接处移开。新拆层请求独立 `left_arm`、`right_arm`，袖子和手持物归各自手臂。渲染按 alpha 分析出的附着点旋转，以躯干中心识别左右侧，兼容偏心构图。另一侧保持独立的轻微呼吸。

已有合并素材仅在两手之间确实存在透明间隙时分成两个显示区域；图案相连、分析失败或无法可靠区分时保持静止。不会强行切开连接的图案。复杂交叉、举手和遮挡关节仍需看图验收。此修复沿用已有分层渲染路线，不等同于完整 Cubism 绑定。

## 真机发现与处理

在用户的 Android 16 手机上复现旧版点击时空手脱离衣袖。原拆层素材不仅合并两手，还缺少完整袖口；一张明确命名为 `base background` 的背景又被旧解析器当成 `detail` 显示。

- 依据缓存付费响应中的明确名称恢复背景角色，渲染时隐藏 Seedream 背景。不会按颜色猜测或删除正常配件。
- 启动和重新选择旧缓存图层时都恢复分类，无需再次付费。
- 新增“修复双臂连接”，复用当前选图及其他图层，仅请求完整左右手臂，包含肩根、袖口和手持物。需用户明确确认；同一选图修复成功后不会再次扣费。
- 网络中断后保留付费响应。下载或解析失败可继续本批，结果不确定的请求阻止自动重发。无独立双臂的响应不覆盖当前形象。
- 已保存的形象可直接进入预览和修复，再调整描述仍走原流程。

本次真机实际通过正常 App Provider 调用 1 次 Flash，返回 3 张图（底图、左臂、右臂），请求状态 `done`。在预览中确认袖口补齐后保存到原角色，点击截图显示空手独立挥动、拿球拍的手保持原位；截图中没有旧版连接断开现象。没有读取或导出手机 API Key，未改动人格、记忆、聊天和模型设置。

## image 参数错误

手机缓存确认失败为 HTTP 400 `InvalidParameter`，参数 `image`。旧记录未保留服务端完整文本，因此不能断言该次拒绝的唯一原因。

拆层现在先由 Android 解码、按 EXIF 转正，再编码为标准 PNG，以实际尺寸校验像素数、宽高比和 Base64；转换结果按内容缓存。新候选指定 PNG 输出。图片扩展名不作为编码依据。

此前桌面验证原 JPEG 请求复现 `InvalidParameter / image`，PNG 请求成功返回底图和 7 层；本次手机原选图（JPEG、2048×2048）经原生 PNG 规范化后修复双臂成功。该结果支持规范化输入，但不保证服务端所有 image 错误都由编码造成。未自动升级到更贵模型或自动付费重画。
