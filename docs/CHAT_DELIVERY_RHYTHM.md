# Chat delivery rhythm — 0.12.1

Literal full stops (`.` / `。`, repeated/mixed/whitespace) are saved as complete user messages with silence disposition, without model calls, extraction, artificial delay or assistant acknowledgment. Recovery does not re-extract these empty gestures. Other inputs still have context-dependent model decisions, including an empty messages array: questions, ellipses, emoji, distress and help requests are not discarded by this gate. Prompt guidance explicitly permits silence for repetitive empty/finished exchanges; it is not a guarantee that every ambiguous input will be classified correctly by a provider.

Ordinary prose is split at line breaks after the full model response is parsed, preserving code blocks and list formatting. Existing explicit message arrays remain supported, with a bounded 12-bubble delivery normalization. Sentences on one line are not blindly split at punctuation. This applies to direct-chat responses; proactive notifications keep their existing grouped notification delivery behavior.

Each direct-chat bubble, including the first, waits for a deterministic composition interval: 650ms plus weighted text length (roughly 105ms per Han character; lower weight for Latin characters), capped at 12 seconds per bubble. Model/network elapsed time is credited only to the first bubble, with a minimum 350ms reveal delay. Subsequent bubbles get their own composition interval. Long generated answers therefore arrive more slowly than short reactions without random no-response decisions. Full streaming remains internal; character activity stays thinking during generation and switches to talking when the first complete bubble is delivered. Actual persistence timestamps reflect reveal time. The chat lease covers the bounded delivery budget.

Regression tests cover repeated full stops, meaningful punctuation preservation, code/list formatting, paragraph splits, length/latency-based pacing, model output completion before reveal, per-bubble persistence visibility and restart recovery. No paid API or device test is required for these deterministic behaviors. Model-dependent conversational judgment remains subject to user acceptance.
