# 原创角色、已有角色与 DS 绘图描述（0.17.1）

## 流程

用户不是只能创建互联网上已存在的角色。现有 `Persona` 和角色 Runtime 保持不变，这次调整形象创建前的绘图流程：

- **原创设计 / OC / 自设 / 只有外观描述**：DS 理解要求 → 不搜索网页 → DS 编写完整绘图描述 → 用户确认生成 → 豆包生成 3 张候选 → 视觉核对 → 选择、拆层及原有预览。
- **复现已有作品角色**：DS 理解身份 → 搜索公开资料及图片 → DS 初步核对 → 用户确认参考 → DS 根据原要求和已确认观察编写绘图描述 → 豆包生成候选。
- **上传自己的原创参考**：直接检查上传图片，不寻找其网上“原型”；确认参考后编写描述并生图。
- **直接动态化上传图片**：继续复用原有直接拆层路径，不强行先生成另一张图。

给原创角色起名字不代表它是已有 IP；没有名字也不应出错。真实 DS 测试中，一个仅有外观的原创请求返回了空 `subject`，现在允许这种输出并以“原创角色”作展示名，不要求用户补作品名。已有角色的空身份、低置信度或无法定位到原文的名字仍会停止确认，不凭空冒认身份。

DS 的“事实简报”和“创作提示词”分开保存：事实简报继续只保留用户原话或实际参考观察；原创提示词允许为未指定部分设计协调的服装/细节。已有角色不凭模型记忆擅自改造。原始用户要求、确认参考和后续通过的候选锚图仍传给豆包，参考观察不是一段虚构的网络资料。

## 保存与费用

新批次使用 `promptVersion=4`，在付费调用之前把 `imagePrompt` 保存进本地草稿，三张候选共享这份设计。DS 故障或输出无效时停止，不偷偷退回固定模板去花豆包额度。重启、失败继续和普通核对会复用保存的描述及图片。

新缓存包含编写好的提示词；不同设计不会误用同一缓存。已有 v2/v3 批次沿用原来的提示词路径和缓存键，避免升级后重发已经付费或结果不确定的请求。旧批次不会被自动重新编写/重画；修改描述创建新草稿，或已完成候选后明确创建新一批，才使用新流程。Pro 生图、Flash 拆层的独立路由继续有效。

DS 编写提示词的调用计入 `visual_prompt_composition`，费用页显示“绘图描述整理”。不包含平台内置 Key，仍使用用户配置的聊天模型/Key；默认是 DeepSeek。原画及拆层仍使用用户自己的豆包 Key。

## 截图中的 HTTP 400

截图显示服务商返回内容审核拒绝；只凭截图无法知道具体拒绝的是输入参考、文字还是模型输出，也不能认定是角色版权、某个词或整个模型不可用。现在根据安全保留的错误码给出更准确提示：

- `InputImage...`：参考图未通过服务商审核。
- `InputText...`：绘图文字未通过服务商审核。
- `OutputImage...`：这次生成结果未通过审核，不等于用户描述或参考图违规。
- 无法确定环节：保留通用拒绝提示，详情显示错误码和请求编号。

失败会停止本批，保留已经完成的候选；不自动切换模型、连发请求或尝试规避服务商审核。DS 正常编写提示词可以改善输入组织，**不能保证消除服务商内容审核拒绝**。本轮未新增豆包生图验证，不声称截图中的具体请求已经成功生成。
