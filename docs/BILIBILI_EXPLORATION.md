# Bilibili exploration

Nyvemi's Android maintenance cycle explores Bilibili independently of the permission to send proactive messages. The per-character exploration switch lives under Settings → 来信与通知. Discovery uses the character's interests to pick a public ranking category, then scores unseen candidates locally. A character can save an experience without generating a notification. Successful discovery checks run at most once every four hours per character; source failures wait 30 minutes.

With 用 DeepSeek 找 B 站视频 enabled, Android maintenance uses DeepSeek's [official Search API](https://api-docs.deepseek.com/guides/search/) to find public video links using one of the character's own interests. This uses the key already configured for the official DeepSeek endpoint. DeepSeek receives the search term and domain filter. A search with results costs $0.00075 and appears in the usage ledger. The switch starts off for existing and new users. The app filters results to canonical Bilibili video URLs, removes tracking parameters, and treats indexed snippets as search evidence.

The optional 扫码连接 B 站 button starts Bilibili's website sign-in, as used by several DSH community plugins. The app renders the QR code locally and polls only while the screen is active. The user confirms in Bilibili. Android secure storage holds the limited website session separately from chat, exported character data and diagnostics. Disconnecting removes the local session. The session is sent only to a small set of Bilibili HTTPS read endpoints. The public Open Platform account OAuth and its own-submission scopes are separate from this website flow.

When connected, the app checks for available subtitles on a shortlist of up to three interesting unseen videos and stops on a provider denial. It checks the video and part identifiers and requires the subtitle track to match the separately returned video metadata before requesting it. The subtitle host receives no login credentials. Videos without a verified available track yield metadata-only experiences. The app samples a limited excerpt, which can be retained in the local experience and used as context with the user-configured model. During chat the character can also read a linked video's subtitles with the same checks.

The existing Experience engine decides if the result should create a delayed share intention. The character can decline to send it. Quiet hours, recent activity, notification permissions and daily limits still govern delivery. The timeline labels subtitle evidence and metadata separately. Developer Mode shows the exploration trigger, outcome, available candidate count and evidence category. Bilibili can decline or change its website responses, including for signed-in sessions.

Relevant checks are in `tests/bilibili-session.test.ts`, `tests/bilibili-captions.test.ts` and `tests/background-exploration.test.ts`.
