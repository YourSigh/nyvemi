# 0.19.1：开场发消息节奏和姓名理解

开场原先绕过了正式聊天的发送队列，一次事务直接把接话和下一题标成已发送。现改为持久化 outbox、逐条发布，复用正式聊天的字数加权 typingDelay：短句较快、长句较慢，第一条抵扣实际模型等待时间但至少 350ms，后续每条独立等待，单条最长 12 秒。开场、接话、下一题、结束语都走这个流程。等待时顶部显示“正在输入…”，下一题真正发出后才开放推荐答案。

每个可见气泡和发送游标在同一事务更新；重进页面、进程恢复和导入角色后只续发未发送消息，不重新请求模型，也不一次倾倒全部气泡。普通聊天的 interrupted recovery 不再提前解锁这些消息。

名字使用独立 `hatching_name` 结构化模型调用，返回纯名字、自然接话，含糊时返回 null 和确认问题。失败保留原名，允许重试；绝不用原始命名句兜底。旧版存在原始命名答案且用户未手动改名时，首次进入聊天自动重新理解一次，保留所有消息。其他偏好继续通过原有开场接话与最后 Persona 生成理解。

真实模型可能对无须填写的确认问题返回 null，解析兼容 null/缺省；名字不明确时仍必须带确认问题。这一情况由真实 DeepSeek 调用发现并加入回归测试。

验证：`npm run check`、`npm run test:live -- --hatching`（最多 6 次 DeepSeek 请求，默认跳过）、Android Debug/Release 构建。真实验证覆盖命名语气词、改口、名字本身带语气词、仅拒绝旧名、请角色自取名。结果写入被 Git 忽略的 `artifacts/live-hatching-name-0.19.1.json`，不包含 Key。
