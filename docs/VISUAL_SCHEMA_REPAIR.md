# 形象创建格式错误修复（0.17.2）

## 用户报告与排查边界

用户在“加参考图”里输入“q版二次元孙颖莎蓝色衣服，黄色鞋子，短头发”，页面报“模型结构化输出不符合格式，请重试”。这个提示来自 DS 回复的 schema 校验，区别于上一次豆包 HTTP 400 审核拒绝。

手机当次的 DS 响应和原始上传图不在开发机上，因此**未完全复现同一次失败，也不能断言当次就是某个字段出错**。用同样文案、将整张用户截图作为近似参考，实际 DS 的要求理解、参考核对及原版提示词编写均曾跑通。整张截图包含界面文字和缩略图，并不等于用户上传的原图。

源码确认了一类可重现的脆弱点：观察特征最多 6 条、每条长度受限，同时不允许任何附加字段。模型多返回第 7 条正确观察、附加一段说明或用单图结果包装，就会使整个步骤失败，之前的通用错误又丢失了具体阶段与字段。这次修复这些边界，并增加诊断，避免把推测当作已知根因。

## 改动

- 正式 DS 的形象结构化请求使用 `response_format: {type: 'json_object'}`，按[官方 JSON 模式要求](https://api-docs.deepseek.com/guides/json_mode/)保留 JSON 示例和输出预算。普通聊天与自定义兼容接口不新增这个参数。
- 观察/问题列表接受有界的更多条目和文字，再本地整理为原有展示长度。未知附加说明会被忽略，不进入执行路径。
- 单图核对可接收直接对象或 `checks` 里唯一一项；多图核对依然检查结果数量。含多个结果的包装不会被擅自当成一个角色。
- 原创角色允许空/缺省名字与缺省搜索词；已有角色的空身份仍会停止确认。
- `namedCharacter`、置信度、`match/uncertain/mismatch`、必须的观察字段及提示词内容继续校验。不把字符串 `false` 强转为布尔值，不把未知状态当作通过，不凭空补出成功决定。
- 新增 `StructuredOutputError`，区分非法 JSON、schema 错误、空回复、输出截断。界面显示“角色要求理解 / 参考图核对 / 绘图描述整理”等阶段，折叠详情显示安全字段路径与错误类型。
- Developer Mode 的 Error 记录同样保留安全诊断。不会记录原始响应、校验 message、字段值、图片字节、请求头或 API Key；非预设字段路径被替换为 `$field`。
- 结构校验在 API 统计成功标记之前执行，失败仍保留已经返回的 token 用量；不再出现 HTTP 成功但 schema 失败仍计成功的情况。

不做自动模型重试、不改用更贵模型、不把错误回退成通过。图像 Provider、候选/拆层缓存键和已付费回执保持原样；这次没有重新画图。

## 验证

离线新增覆盖：额外条目与元数据、单图包装、未知/缺失状态拒绝、必需字段不猜测、缺失提示词拒绝、官方 JSON 模式与自定义接口兼容、失败统计与 token 记录、无自动重试、空/截断/非法 JSON、诊断脱敏、UI 折叠详情与日志持久化。

`npm run verify`：lint、typecheck、**347 项离线测试**、Kotlin 单元测试任务和 Android Debug 构建通过；16 项收费/外部调用测试默认跳过。

真实探针：`node scripts/test-live.cjs --visual-schema`，持久预算上限 **4 次 DS 请求，已用 4/4**，不重置旧生图/DS 测试预算。开发目录 `artifacts/live-visual-schema/` 保留响应缓存和结果，未纳入 APK/Git。

- 原始代码用同文案和整张截图近似验证，3 次 DS 请求均通过（理解、核对、编写）。
- 修复后新增 1 次正式 JSON 模式参考图核对，成功返回 `match`、5 条特征、1 条观察问题。要求理解复用了前一轮收到的响应。
- 新核对观察有所变化，后续编写提示词会产生另一条文字请求；测试预算已满，脚本阻止了它，没有发出请求。最终探针范围明确限定为“要求理解 + 上传参考核对”，缓存重放通过；不声称这轮又验证了提示词编写或豆包生图。
- `imageGenerationRequests=0`。没有重新画图、拆层、真机或模拟器测试。

具体现场原因为何仍需手机这次原始失败信息；新版再次遇到异常时，可从“错误详情”获得阶段和字段，不再只有一句通用报错。
